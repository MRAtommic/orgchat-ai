# แผนงานสำหรับ Antigravity: ปฏิทินกิจกรรม (แก้การ์ดชิดซ้าย + ปฏิทินเต็มจอ + ดูรายละเอียดเต็ม)

## กติกาที่ต้องทำตามตลอด
- ห้ามอ่าน/แก้ `webai/.env` ห้าม push git ห้ามทดสอบกับ `chat_history.db` จริง (ใช้ DB ชั่วคราว/เซิร์ฟเวอร์ทดสอบ)
- แก้เฉพาะที่ระบุ ไม่รื้อส่วนอื่นของปฏิทิน (ลิงก์ LINE, Export .ics, Archive, To-Do ต้องยังทำงาน)
- static/templates โหลดสดเมื่อรีเฟรช (Ctrl+F5) ส่วน Python ต้องให้ผู้ใช้รีสตาร์ตเซิร์ฟเวอร์ (แผนนี้ส่วนใหญ่แก้ฝั่งหน้าเว็บ)
- หลังทดสอบ ปิดเซิร์ฟเวอร์ทดสอบที่เปิดเอง รายงานผลเป็นภาษาไทย ตรงไปตรงมา ข้อไหนไม่ได้ทดสอบจริงให้บอก

## งานที่ 0 (ความปลอดภัย ทำก่อนเสมอ): ช่องโหว่ XSS ในรายการ "นัดหมายเร็วๆ นี้"
**พบระหว่างอ่านโค้ด:** `renderUpcoming()` ใน `static/js/chat.js` (~6541–6567) ใส่ข้อมูลลง HTML ตรงๆ โดยไม่ escape: `${s.title}`, `${s.desc}`, `${s.display_name || s.owner}`, `${s.avatar_url}` (ใน `src=`), และ `${dateStr} · ${s.time}` กำหนดการเป็นข้อมูลที่ "สมาชิกคนอื่นในองค์กรเห็นได้" (สถานะ Public) → สมาชิกที่ประสงค์ร้ายตั้งชื่อกิจกรรมเป็นโค้ดสคริปต์แล้วทำให้คนอื่นรันโค้ดได้ (Stored XSS) รอบตรวจ XSS ก่อนหน้าพลาดจุดนี้
**แก้:**
1. ใช้ `escHtml()` (มีอยู่แล้วในโปรเจกต์) กับ title, desc, display_name, owner, time และใช้ `_safeUrl()` กับ `avatar_url` ก่อนใส่ใน `src`
2. ตรวจ `renderCalendar()` ซ้ำว่า escape ครบทุกจุด (ชื่อวันหยุดและ title ใช้ `escHtml` อยู่แล้ว แต่เช็ก `s.time`, `s.category`, `s.id` ที่ลงใน attribute/onclick ให้เป็นค่าที่ปลอดภัย เช่นแปลง id เป็นตัวเลขด้วย `Number()`)
3. ตรวจโมดอลใหม่ (งานที่ 4) ให้ escape ทุกค่าตั้งแต่แรก
**ทดสอบ:** สร้างกิจกรรมชื่อ `<img src=x onerror=alert(1)>` และคำอธิบาย `<script>alert(2)</script>` บน DB ทดสอบ → ในรายการเร็วๆ นี้, ในช่องปฏิทิน, ในโมดอลใหม่ ต้องแสดงเป็นข้อความธรรมดา ไม่มี alert และ Console ไม่มี error

## งานที่ 1: การ์ด "แก้ไขนัดหมาย" ชิดซ้าย (บัค — พบสาเหตุแล้ว)
**สาเหตุ:** `#scheduleModal` เป็นกล่องซ้อนทับเต็มจอที่จัดกลางด้วยคลาส `flex items-center justify-center` แต่
- `closeScheduleModal` (~บรรทัด 6926–6927) **ลบ** คลาส `flex items-center justify-center` ออกเมื่อปิด
- `openAddModal` (~6646–6647) **ใส่คืน** คลาสเหล่านั้น → ปุ่ม "เพิ่มกิจกรรม" จึงอยู่กลางจอปกติ
- แต่ `editSchedule` (~6688) ทำแค่ `classList.remove('hidden')` **ไม่ใส่คืน** → หลังปิดโมดอลครั้งแรก การเปิดแบบ "แก้ไข" ทุกครั้งจะเป็น block ธรรมดา การ์ดจึงไปชิดซ้ายบน (ตรงกับภาพ)
**แก้ (ทางที่แนะนำ):** ทำ helper `openScheduleModal()` / `closeScheduleModal()` ตัวเดียวที่จัดการคลาสให้ถูกทุกครั้ง ให้ `openAddModal`, `editSchedule` และงานที่ 4 เรียกใช้ตัวเดียวกัน หรือง่ายกว่านั้น: เลิกลบ `flex items-center justify-center` ตอนปิด (ให้ `hidden` อย่างเดียวควบคุมการซ่อน เพราะมีคลาส `flex` อยู่ใน HTML อยู่แล้ว — ระวัง `hidden` กับ `flex` ชนกัน ให้ใช้ `hidden` อย่างเดียวสลับ และตรวจว่า Tailwind ที่คอมไพล์ไว้ลำดับคลาสถูก)
- ตรวจโมดอลอื่นในหน้าเดียวกันที่ใช้รูปแบบ add/remove `flex` แบบเดียวกัน อาจมีบัคแบบเดียวกัน (ค้นคำว่า `classList.add('flex', 'items-center', 'justify-center')` ใน `static/js/*.js`)
**ทดสอบ:** (ธีมสว่างและมืด, คอมและมือถือ) เปิดแก้ไข → ปิด → เปิดแก้ไขอีกกิจกรรม → ปิด → กดเพิ่ม → ปิด → แก้ไข: การ์ดอยู่กลางจอทุกครั้ง, กด Esc/คลิกพื้นหลัง/ปุ่ม X ปิดได้, ปุ่มบันทึกยังบันทึกได้

## งานที่ 2: ปฏิทินเต็มความกว้าง + ย้ายการ์ดขวาลงด้านล่าง
**ตอนนี้:** แถวหลักเป็น `lg:flex-row` — ปฏิทิน `flex-1` + ไซด์บาร์ `lg:w-80` ทางขวา และทุกบล็อกครอบด้วย `max-w-[1600px]`
**ต้องการ:** ปฏิทินกว้างเต็ม แล้วการ์ด "นัดหมายเร็วๆ นี้" กับ "To-Do" อยู่ใต้ปฏิทิน
**แก้ใน `templates/index.html`:**
1. เปลี่ยนคอนเทนเนอร์ (~บรรทัด 3226) จาก `flex flex-col lg:flex-row ... items-start` เป็นแนวตั้ง `flex flex-col` ปฏิทินกว้าง 100%
2. ย้ายไซด์บาร์ไปใต้ปฏิทิน เป็นกริด 2 คอลัมน์บนจอใหญ่ (`grid grid-cols-1 lg:grid-cols-2 gap-6`) การ์ดละคอลัมน์ (นัดหมายเร็วๆ นี้ | To-Do) มือถือเป็นคอลัมน์เดียว ปรับ `w-full lg:w-80 flex-shrink-0` ออก
3. ความกว้างสูงสุด: เปลี่ยน `max-w-[1600px]` ของหัวเรื่อง/แถบเครื่องมือ/ปฏิทิน/การ์ดให้ **สอดคล้องกันทั้งหมด** และกว้างขึ้นเต็มพื้นที่ (เช่น `max-w-none` หรือ `max-w-[2200px]` พร้อม padding ซ้ายขวา) ตามที่ผู้ใช้ต้องการ "เต็มเลย" ห้ามให้ปฏิทินกว้างไม่เท่าส่วนหัว
4. ช่องวันที่ให้สูงขึ้นตามพื้นที่ (เช่น `min-h-[110px] lg:min-h-[140px]` หรือใช้ `grid-auto-rows: minmax(...)`) เพื่อใช้พื้นที่ที่ได้เพิ่ม
5. `#upcomingSchedules` เดิมจำกัด `max-h-64` — เมื่อกว้างขึ้นให้จัดรายการเป็น 2–3 คอลัมน์ในการ์ด หรือเพิ่มความสูง (ผู้ใช้อยากเห็นรายละเอียดกำหนดการ)
6. มือถือ (ความกว้าง ≤ 640px): ปฏิทินยังต้องเลื่อนแนวนอนหรือย่อได้เหมือนเดิม (`min-w-[560px]` ในโค้ดเดิม) ไม่ทำให้หน้าเลื่อนข้าง
**ทดสอบ:** ความกว้าง 1920 / 1366 / 768 / 375, ธีมสว่าง/มืด ดูว่าปฏิทินเต็ม การ์ดอยู่ล่าง ไม่มีส่วนล้น/เลื่อนข้างทั้งหน้า

## งานที่ 3: ช่องวันที่มีกิจกรรมหลายอัน → ย่อแล้วมีปุ่ม "+N เพิ่มเติม"
**ปัญหา:** ตอนนี้ช่องวันแสดงกิจกรรมทุกอัน ช่องจะยืดสูงไม่สม่ำเสมอเมื่อมีหลายรายการ
**แก้ใน `renderCalendar()`:**
1. ในแต่ละช่องแสดงสูงสุด 2 รายการ (จอใหญ่ 3) เรียงตามเวลา แล้วถ้ามีเกินแสดงแถบ "+N เพิ่มเติม" (นับรวมวันหยุดด้วยหรือแยกบรรทัด — ให้วันหยุดแสดงเป็นแถบบนสุดเสมอ ไม่นับในโควตา)
2. ป้าย PUBLIC/OVERDUE เล็กมากอยู่แล้ว (6–7px) — ตอนย่อให้คงตัวอ่านออก ใช้จุดสี/ไอคอนแทนข้อความถ้าแน่น
3. คลิกที่กิจกรรมในช่อง = เปิดโมดอลรายละเอียด (งานที่ 4) ไม่ใช่เปิดโมดอลแก้ไขตรงๆ เหมือนเดิม (การแก้ไขทำจากในโมดอลรายละเอียดอีกที)

## งานที่ 4: โมดอล "รายละเอียดกำหนดการของวันนั้น" (ดูได้เต็มเมื่อมีหลายรายการ)
**ต้องการ:** กดที่ช่องวันที่ (หรือ "+N เพิ่มเติม" หรือกิจกรรม) แล้วเห็นรายการกำหนดการทั้งหมดของวันนั้นแบบเต็ม
**ออกแบบ:** โมดอลใหม่ `#dayDetailModal` (สไตล์เดียวกับ `#scheduleModal`: พื้นหลังมืดเบลอ, การ์ดกลางจอ, ปิดด้วย X/Esc/คลิกพื้นหลัง, เลื่อนในโมดอลได้ `max-h` + `overflow-y-auto`, มือถือเต็มความกว้าง)
- หัวโมดอล: วันที่แบบไทยเต็ม (เช่น "วันพฤหัสบดีที่ 5 พฤศจิกายน 2569") + ชื่อวันหยุดถ้ามี + ปุ่ม "เพิ่มกิจกรรมในวันนี้" (เรียก `openAddModal(dateStr)`)
- เนื้อหา: การ์ดของแต่ละกิจกรรมเรียงตามเวลา แสดง **ครบ ไม่ตัดข้อความ**: ชื่อ, เวลา, หมวดหมู่ (สี/ไอคอนตามเดิม), คำอธิบายเต็ม (ขึ้นบรรทัดใหม่ตามที่พิมพ์), สถานะ (todo/done/overdue), การมองเห็น (สาธารณะ / เฉพาะแผนก / เฉพาะบุคคล), เจ้าของ (ชื่อ+รูป)
- ปุ่มในแต่ละการ์ด: แก้ไข (`editSchedule(id)` → ปิดโมดอลรายละเอียดก่อนเปิดโมดอลแก้ไข), ทำเครื่องหมายเสร็จ/ยังไม่เสร็จ (`toggleScheduleStatus`), ลบ (`deleteSchedule` มี confirm เดิม) — แสดงเฉพาะที่ผู้ใช้มีสิทธิ์ตามที่ระบบเดิมกำหนด (ดูวิธีเช็กสิทธิ์เจ้าของ/แอดมินในโค้ดเดิมและ `routes/admin.py` ฝั่งเซิร์ฟเวอร์ อย่าเชื่อแต่ฝั่งหน้าเว็บ)
- วันที่ไม่มีกิจกรรม: กดแล้วเปิดโมดอล "เพิ่มกิจกรรม" เหมือนเดิม (ไม่ต้องเปิดโมดอลรายละเอียดว่างๆ)
- **ย้ายพฤติกรรม "เก็บเข้ากรุของวันที่ผ่านมา" ออกจาก `confirm()` ที่ผูกกับการกดช่องวัน** (ตอนนี้ถ้ากดวันที่ผ่านมาแล้วที่มีกิจกรรม จะเด้ง confirm ถามเก็บเข้ากรุ ซึ่งชนกับการกดเพื่อดูรายละเอียด และเรียก API ที่เก็บ **ทุกกิจกรรมที่ผ่านมา** ไม่ใช่เฉพาะวันนั้น — น่าสับสน) ให้เป็นปุ่ม "เก็บเข้ากรุ" ในโมดอลรายละเอียด หรือปล่อยให้ใช้ปุ่ม "เก็บเข้ากรุ (Archive)" ด้านบนอย่างเดียว และ **ข้อความยืนยันต้องบอกตรงๆ ว่าจะเก็บกรุกี่รายการและทั้งหมดหรือไม่**
- ทุกค่าที่ใส่ HTML ต้อง `escHtml` (ดูงานที่ 0) และ `data-id`/onclick ใช้ตัวเลขที่แปลงแล้ว
- คีย์บอร์ด: โฟกัสเข้าโมดอลตอนเปิด, Esc ปิด, ตั้ง `role="dialog"` `aria-modal="true"` `aria-label`
**ทดสอบ:** วันที่มี 0 / 1 / 5 / 15 กิจกรรม (รายการยาวต้องเลื่อนในโมดอลได้ ไม่ล้นจอ), ข้อความคำอธิบายยาวและหลายบรรทัดแสดงครบ, ปุ่มแก้ไข/เสร็จ/ลบทำงานแล้วปฏิทินและรายการเร็วๆ นี้อัปเดตทันทีโดยไม่ต้องรีเฟรช, ผู้ใช้ที่ไม่ใช่เจ้าของไม่เห็นปุ่มแก้ไข/ลบ (และเซิร์ฟเวอร์ปฏิเสธถ้ายิงตรง), ธีมมืด/สว่าง, มือถือ

## งานที่ 5 (บัคเล็กที่พบระหว่างทาง ทำพร้อมกันได้): "วันนี้" คิดด้วย UTC
`renderCalendar()` และ `renderUpcoming()`/ส่วนอื่น ใช้ `new Date().toISOString().split('T')[0]` เป็น "วันนี้" ซึ่งเป็นวันที่ตามเวลา UTC → ช่วงเที่ยงคืนถึง 07:00 น. เวลาไทย "วันนี้" จะเป็นเมื่อวาน ทำให้ป้าย OVERDUE/การไฮไลต์วันนี้ผิด (ตอนใช้ `todayStr`/`isPast`) แก้เป็นวันที่ตามเวลาท้องถิ่นของเครื่อง (ประกอบจาก `getFullYear/getMonth/getDate`) ทำเป็นฟังก์ชันเดียว `localDateStr(d)` ใช้ซ้ำทุกจุดในไฟล์ปฏิทิน และตรวจ `openAddModal` (~6655: `now.toISOString()` ตั้งค่าวันเริ่มต้นของโมดอลก็คลาดเช่นกัน)
**ทดสอบ:** ปลอมเวลาเครื่องเป็น 01:00 น. (เวลาไทย) แล้วดูว่าวันนี้ไฮไลต์วันที่ถูกต้อง ไม่ขึ้น OVERDUE ผิดวัน

## เกณฑ์ที่ถือว่าเสร็จ
1. ใส่สคริปต์ XSS ในชื่อ/คำอธิบายกิจกรรมแล้วไม่ทำงานในทุกจุด (งาน 0)
2. โมดอลแก้ไขอยู่กลางจอทุกครั้ง แม้เปิด-ปิดซ้ำ (งาน 1)
3. ปฏิทินเต็มความกว้าง การ์ดนัดหมายเร็วๆ นี้และ To-Do อยู่ใต้ปฏิทิน (งาน 2)
4. ช่องวันที่มีหลายกิจกรรมไม่ยืดเกะกะ และกดดูรายละเอียดทั้งหมดแบบเต็มได้ (งาน 3–4)
5. ใช้ได้ทั้งธีมสว่าง/มืด คอมและมือถือ (375/768/1366/1920) ไม่มีเลื่อนข้างทั้งหน้า Console ไม่มี error
6. ฟีเจอร์เดิมยังทำงาน: เพิ่ม/แก้/ลบ/เสร็จ กิจกรรม, ค้นหา, กรองหมวดหมู่, Export .ics, Archive, To-Do, การแจ้ง LINE ตอนแก้ไข
7. เทสต์ที่เกี่ยวข้องผ่าน (รันทีละไฟล์) และรายงานผู้ใช้เป็นภาษาไทยว่าแก้อะไร/ทดสอบอะไร/อะไรยังไม่ได้ทดสอบ
