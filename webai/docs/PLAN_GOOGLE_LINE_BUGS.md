# แผนงานสำหรับ Antigravity: แก้ 3 อาการที่ผู้ใช้จริงรายงาน (เชื่อม Google/อีเมล + Morning Brief + หน้า "ยังไม่ได้ยืนยันแอป")

## กติกาที่ต้องทำตามตลอด
- ห้ามอ่าน/แก้/แสดงค่าใน `webai/.env` ห้ามพิมพ์ secret/token ลงรายงานหรือ log ที่ส่งต่อ ห้าม push git
- ห้ามทดสอบกับ `chat_history.db` จริง ใช้ DB ชั่วคราว (`DB_PATH`, `DATA_DIR`, `VECTOR_BACKEND=python` ชี้ไป temp เหมือน `tests/isolated/*_scenarios.py`)
- ห้ามเรียก Google/LINE จริง ใช้ mock (`unittest.mock.patch`) ทุกครั้ง ห้ามกรอกรหัสผ่านหรือ credential ลงเว็บจริง
- รันเทสต์ทีละไฟล์ (รวมชุดเดียวหน่วยความจำไม่พอ) ปิดเซิร์ฟเวอร์ทดสอบที่เปิดเองเมื่อเสร็จ
- ก่อนจบ ต้อง `python -c "import app_server"` ผ่าน และ `node --check` ผ่านทุกไฟล์ JS ที่แก้ (เคยมีไฟล์พังค้างกลางทางทำให้แอปเปิดไม่ขึ้น)
- รายงานผลเป็นภาษาไทย ตรงไปตรงมา ส่วนที่ทดสอบกับของจริงไม่ได้ให้บอกชัด อย่าอ้างว่าเสร็จถ้าไม่ได้ทดสอบ
- ผู้ใช้ต้องรีสตาร์ตเซิร์ฟเวอร์หลังแก้ Python และกด Ctrl+F5 หลังแก้ JS (ขึ้นเลขเวอร์ชัน `?v=` ของไฟล์ JS ใน `templates/index.html` ทุกครั้งที่แก้)

## ที่มา (ผู้ใช้จริงรายงานผ่านแชท)
1. กดเชื่อม Google แล้วเจอหน้าของ Google "Google ยังไม่ได้ยืนยันแอปนี้"
2. กด "เชื่อมอีเมล/Google" แล้วเจอหน้าเปล่าแสดง JSON ดิบ `{"error":"internal_error","message":"เกิดข้อผิดพลาดภายในระบบ กรุณาลองใหม่อีกครั้ง หรือติดต่อผู้ดูแลระบบค่ะ","ok":false}`
3. กดปุ่ม "ทดสอบ Morning Brief" (การ์ด "การเชื่อมต่อ LINE ส่วนตัว") แล้วไม่ได้รับอะไร ทั้งที่การ์ดแสดง "เชื่อมต่อแล้ว (LINE ID: U5a4b7ddf0…)"

## งาน A: JSON ดิบ `internal_error` ตอนกดเชื่อม Google/อีเมล
**สิ่งที่รู้แล้ว (จากโค้ด):**
- `static/js/chat.js` ฟังก์ชัน `bindMyGoogleAccount()` (~บรรทัด 12559) พยายามใช้ Google One Tap ก่อน แล้วถ้าไม่แสดง/ถูกข้าม จะ **เปลี่ยนหน้าทั้งหน้า** ไป `/api/auth/google/start?mode=personal` (นำทางด้วย `window.location.href`) ทำให้ถ้า route นั้นหรือ `/api/auth/google/callback` (ใน `routes/auth.py` ~บรรทัด 356–560) ตอบ JSON/500 ผู้ใช้จะเห็น JSON ดิบแทนหน้าที่อ่านรู้เรื่อง
- ตัวดักข้อผิดพลาดรวม `@app.errorhandler(500)` (`app_server.py` ~บรรทัด 747) ตอบ `internal_error` โดยไม่บอกสาเหตุ (ควร log ไว้แล้วด้วย `logger.exception`)
**สิ่งที่ต้องทำ:**
1. **หาสาเหตุจริงก่อน ห้ามเดา:** เปิดไฟล์ log ของแอป (ดูโฟลเดอร์ `logs/` และ `bot_debug.log` แบบอ่านอย่างเดียว ค้นคำว่า `Global 500 Error Handler` หรือ `OAuth2 callback error` ใกล้เวลาที่เกิด) หรือจำลองด้วย Flask test client เรียก `/api/auth/google/start` และ `/api/auth/google/callback` โดย mock `oauth2_service`/`google_manager` ให้ล้มแบบต่างๆ (ไม่ตั้งค่า OAuth, แลก token ล้มเหลว, `setup_user_workspace` โยน exception, อีเมลซ้ำกับบัญชีอื่น) หาว่าอันไหนให้ 500
2. **แก้ที่ต้นเหตุ** ตามที่พบ
3. **ผู้ใช้ต้องไม่เห็น JSON ดิบ:** ใน `/api/auth/google/start` และ `/api/auth/google/callback` ถ้าล้มเหลวให้ตอบเป็นหน้า HTML มีปุ่มกลับ (รูปแบบเดียวกับ `render_link_error` ที่ใช้กับ LINE) หรือ redirect กลับ `/?google_error=<รหัส>` แล้วให้หน้าเว็บขึ้น toast ภาษาไทย (ห้ามใส่ข้อความ exception ดิบลง URL)
4. ตรวจเส้นทาง `/api/user/bind-google` (`routes/auth.py` ~บรรทัด 3740) ด้วย: ไม่มี `GOOGLE_CLIENT_ID`/ไลบรารี → ต้องตอบข้อความที่ผู้ใช้เข้าใจ และถ้าอีเมลซ้ำบัญชีอื่นต้องแจ้งชัด (ทำอยู่แล้ว ให้ยืนยันด้วยเทสต์)
**ทดสอบ (DB ชั่วคราว + mock):** แต่ละกรณีล้มเหลวข้างต้นได้หน้า/ข้อความภาษาไทยที่อ่านรู้เรื่อง ไม่ใช่ JSON ดิบ, กรณีสำเร็จยังผูกอีเมลได้และล็อกอินด้วย Google ครั้งถัดไปเข้าบัญชีเดิม, เพิ่มเทสต์ไว้ใน `tests/` (ไฟล์ใหม่ เช่น `tests/test_google_bind_errors.py`)

## งาน B: หน้า "Google ยังไม่ได้ยืนยันแอปนี้"
**สาเหตุ:** ไม่ใช่บัคในโค้ด คือหน้าจอยินยอม (OAuth consent screen) ของแอปใน Google Cloud ยังเป็นสถานะ Testing/ยังไม่ผ่านการยืนยัน และคำขอสิทธิ์ที่ส่งไปมีขอบเขตระดับ Drive/Sheets (sensitive scopes) ซึ่ง Google แสดงคำเตือนนี้เสมอจนกว่าแอปจะได้รับการยืนยัน ผู้ใช้ที่ไม่ได้อยู่ในรายชื่อ Test users จะเข้าไม่ได้เลย
**สิ่งที่ anti ทำได้ในโค้ด (ลดโอกาสเจอหน้านี้):**
1. แยก "ผูกบัญชี/ล็อกอินด้วย Google" ออกจาก "เชื่อม Drive/Sheets": การผูกอีเมลต้องใช้เฉพาะ ID token แบบ Google Identity Services (ไม่มีขอบเขต Drive จึงไม่ขึ้นคำเตือน) ส่วนการเชื่อม Drive/Sheets เป็นปุ่มแยกที่อธิบายชัดว่าจะขอสิทธิ์อะไร
2. ใน `bindMyGoogleAccount()` เลิกใช้การ **fallback ไป `/api/auth/google/start`** (ซึ่งขอขอบเขต Drive) เมื่อ One Tap ไม่แสดง ให้ใช้ปุ่ม Google ที่เรนเดอร์ด้วย `google.accounts.id.renderButton` (เปิดป๊อปอัปได้เสมอ ไม่ติดช่วงพัก One Tap) แล้วส่ง credential ไป `/api/user/bind-google` เหมือนเดิม
3. ตรวจรายการ scopes ใน `oauth2_service` (ค้น `SCOPES`) ขอเท่าที่จำเป็นจริง ลดสิทธิ์ที่ไม่ได้ใช้
**สิ่งที่ผู้ใช้ (เจ้าของระบบ) ต้องทำเองที่ Google Cloud Console (anti ทำแทนไม่ได้ ให้เขียนเป็นคู่มือสั้นๆ ใน `docs/GOOGLE_OAUTH_GUIDE.md` หรือไฟล์ที่มีอยู่แล้ว `GOOGLE_OAUTH_GUIDE.md`):**
- APIs & Services > OAuth consent screen: ถ้าสถานะเป็น Testing ให้เพิ่มอีเมลที่จะทดสอบ/สอบเป็น **Test users** (สูงสุด 100) หรือเปลี่ยนเป็น In production (ขอบเขต Drive/Sheets ต้องส่งยืนยันกับ Google ใช้เวลานาน)
- ผู้ที่เป็น Test user จะยังเห็นคำเตือนครั้งแรก ให้กด "ขั้นสูง" > "ไปที่ <ชื่อแอป> (ไม่ปลอดภัย)" ซึ่งปกติสำหรับแอปที่ยังไม่ยืนยัน
**ทดสอบ:** ปุ่มผูกอีเมลทำงานจนจบโดยไม่เรียก `/api/auth/google/start` (ตรวจด้วยการอ่านโค้ดและ mock), ปุ่มเชื่อม Drive ยังทำงานเหมือนเดิม

## งาน C: ปุ่ม "ทดสอบ Morning Brief" ไม่ส่งอะไร
**สิ่งที่รู้แล้ว:**
- ปุ่มเรียก `testMorningBriefing()` (`static/js/chat.js` ~บรรทัด 18704) → `POST /api/admin/briefing/trigger` (`routes/admin.py` ~บรรทัด 3827)
- route นี้ **ตอบ `ok: true` เสมอ** แม้การส่ง LINE ล้มเหลวหรือผู้ใช้ไม่มีไอดีที่ส่งได้ (ไม่ตรวจผลลัพธ์ของ `send_line_push_notification`) ผู้ใช้จึงเห็นข้อความสำเร็จแต่ไม่ได้รับอะไร และถ้า `database.get_executive_summary_data` หรือ `create_morning_briefing_flex_bubble` พัง จะได้ `internal_error`
- route ใช้แค่ `@login_required` ทั้งที่ชื่ออยู่ใต้ `/api/admin/` ตรวจว่าตั้งใจให้ผู้ใช้ทั่วไปกดได้หรือไม่ (ปุ่มอยู่ในหน้าตั้งค่าส่วนตัว) และข้อมูลสรุปที่ส่งเป็นข้อมูลระดับองค์กร (การเงิน/ใบลา) **ต้องไม่รั่วให้สมาชิกทั่วไปเห็นเกินสิทธิ์** ให้ตรวจสิทธิ์ (admin/สิทธิ์ดูข้อมูลการเงิน) ก่อนใส่ข้อมูลเหล่านั้นในข้อความ
**สมมติฐานสำคัญที่ต้องตรวจ (น่าจะเป็นต้นเหตุหลัก):** ไอดี LINE ที่แสดงเป็น "เชื่อมต่อแล้ว (LINE ID: U5a4b7ddf0…)" อาจมาจาก **LINE Login** ไม่ใช่จากบอทแชท (Messaging API) ใน `db/chat.py` ฟังก์ชัน `link_line_user(..., is_login=True)` (~บรรทัด 814–838) จะเก็บไอดีจาก LINE Login ลงช่อง `line_login_id` และ **ถ้าช่อง `line_user_id` ว่างอยู่ จะคัดลอกลง `line_user_id` ด้วย** ซึ่งช่องนี้คือไอดีที่ระบบใช้ส่งข้อความ push ผ่านบอท แต่ไอดีผู้ใช้ของ LINE ต่างกันตาม "Provider": channel LINE Login (provider `test_login` ตามหน้า Console) กับบอท Messaging API ถ้าอยู่คนละ Provider ไอดีจะไม่ตรงกัน การ push ไปที่ไอดีนั้นจะล้มเหลวเงียบๆ (LINE ตอบ 400/ไม่พบผู้ใช้) นี่อธิบายอาการ "เชื่อมต่อแล้วแต่ไม่ได้รับข้อความ" ได้พอดี
**สิ่งที่ต้องทำ:**
1. **พิสูจน์สมมติฐาน** ด้วยเทสต์ DB ชั่วคราว: ล็อกอินด้วย LINE Login (mock) บัญชีใหม่ แล้วดูว่า `line_user_id` ถูกเติมด้วยไอดีจาก LINE Login จริงหรือไม่ และ `get_line_id_by_username` (ใช้ส่ง push) คืนไอดีไหน
2. **แยกชัดเจน:** ไอดีจาก LINE Login ใช้เพื่อ "ล็อกอิน" เท่านั้น ห้ามเอาไปใช้เป็นปลายทาง push ผ่านบอทโดยอัตโนมัติ (ยกเลิกการคัดลอกลง `line_user_id` ใน `link_line_user` เมื่อ `is_login=True`) ผู้ใช้ต้องเพิ่มเพื่อนบอทและผูกผ่านบอท (ลิงก์/โทเค็นที่มีอยู่) จึงจะได้ไอดีสำหรับ push ที่ถูกต้อง **ระวังผลกระทบต่อผู้ใช้เดิมที่ผูกไว้แล้ว:** ห้ามลบไอดีเดิมที่ใช้งานได้อยู่ ทำเฉพาะการไม่คัดลอกอัตโนมัติในครั้งต่อไป และเขียนเทสต์ครอบคลุมทั้งผู้ใช้เก่า/ใหม่
3. **UI การ์ด "การเชื่อมต่อ LINE ส่วนตัว"** (`templates/index.html` ~บรรทัด 4080–4110 และ `_renderMySettings` ใน `static/js/chat.js`): แสดง 2 สถานะแยกกัน "ล็อกอินด้วย LINE: ผูกแล้ว/ยังไม่ผูก" และ "รับแจ้งเตือนผ่านบอท: ผูกแล้ว/ยังไม่ผูก (ปุ่มวิธีเชื่อมบอท)" ปุ่ม "ทดสอบ Morning Brief" ให้กดได้เมื่อมีไอดีบอทเท่านั้น ถ้าไม่มีให้ข้อความอธิบายว่าต้องเพิ่มเพื่อนบอทก่อน
4. **แก้ route `/api/admin/briefing/trigger`:** ตรวจผลการส่งจริง (ให้ `send_line_push_notification` คืนค่าสำเร็จ/ล้มเหลวหรือจับ exception แล้วส่งต่อ) ถ้าล้มเหลวตอบ `ok: false` พร้อมเหตุผลภาษาไทยที่ตรงจริง (เช่น "ยังไม่ได้ผูกบอทแชท", "LINE ปฏิเสธ: …") ห้ามตอบสำเร็จทั้งที่ไม่ได้ส่ง ครอบด้วย try/except ไม่ให้เกิด `internal_error` ดิบ และตรวจสิทธิ์ตามข้อด้านบน
5. ตรวจว่า **ตัวส่ง Morning Briefing อัตโนมัติตามเวลา** (ค้น `morning`/`briefing` ใน `app_server.py`, `routes/chat.py`) ใช้ไอดีปลายทางชุดเดียวกัน ถ้าใช่ก็จะล้มเหลวเงียบๆ ทุกเช้าเช่นกัน ให้แก้ให้สอดคล้องและบันทึก log เมื่อส่งไม่สำเร็จ
**ทดสอบ (mock LINE API ห้ามเรียกจริง):** ผู้ใช้ที่มีไอดีบอท → ส่งสำเร็จ ได้ `ok: true`; ผู้ใช้ที่ผูกแค่ LINE Login → `ok: false` ข้อความชัดเจน ไม่ส่งไปไอดี Login; LINE ตอบ 400 → `ok: false` ไม่ใช่ `ok: true`; สมาชิกทั่วไปไม่ได้ข้อมูลการเงินเกินสิทธิ์; เทสต์เดิมที่เกี่ยวกับ LINE (`tests/isolated/line_link_scenarios.py`, `tests/test_line_inbox_isolated.py`, `tests/test_u0_auth_flow.py`) ต้องยังผ่าน

## เกณฑ์ที่ถือว่าเสร็จ
1. กดเชื่อมอีเมล/Google ไม่เจอ JSON ดิบอีก ล้มเหลวแล้วเห็นข้อความภาษาไทยที่บอกว่าต้องทำอะไรต่อ
2. การผูกอีเมลไม่ต้องผ่านหน้า "ยังไม่ได้ยืนยันแอป" (ใช้ ID token) ส่วนการเชื่อม Drive ยังทำงานและมีคู่มือบอกให้เพิ่ม Test users
3. ปุ่ม Morning Brief บอกผลตามจริงเสมอ และผู้ที่ผูกบอทไว้ได้รับข้อความจริง การ์ด LINE แยกสถานะ "ล็อกอิน" กับ "แจ้งเตือนผ่านบอท"
4. เทสต์ใหม่ + เทสต์เดิมที่เกี่ยวข้องผ่าน (ทีละไฟล์) และ `import app_server` กับ `node --check` ผ่าน
5. รายงานสรุปเป็นภาษาไทย: แก้อะไร/ไฟล์ไหน/ทดสอบอะไร/อะไรต้องให้ผู้ใช้ทำเอง (Google Cloud Console, เพิ่มเพื่อนบอท, รีสตาร์ต, Ctrl+F5)
