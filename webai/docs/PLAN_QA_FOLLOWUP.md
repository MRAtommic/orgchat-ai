## 1. ตรวจการแก้ CSS `.hidden` ให้แน่ใจว่าไม่ทำหน้าพัง

การแก้ใน `static/css/components.css`: `.hidden:not([class*='sm:']):not([class*='md:'])…{display:none!important}` อาจทำให้ element ที่ตั้งใจซ่อนบนมือถือด้วยคลาส `hidden md:flex` แสดงบนมือถือด้วย (เพราะตัวเลือกยกเว้นทุก element ที่มี `md:`) และไม่ได้ซ่อนในขนาดเล็ก

- ตรวจด้วย Playwright (Chrome จริง) ที่ 375 / 390 / 768 / 1024 / 1360 / 1920 ทุกหน้า (home, แชท, KB, ปฏิทิน, สมาชิก, ตั้งค่า, Security Audit, หน้าล็อกอิน/สมัคร)
- สำหรับทุก element ที่ใช้ `hidden <breakpoint>:*` ให้ตรวจ `getComputedStyle().display` ที่แต่ละขนาดจอ ว่า **ซ่อนบนจอเล็ก และแสดงตั้งแต่ breakpoint ขึ้นไป** ตามที่ Tailwind ตั้งใจ ทำตารางผล (selector × ความกว้าง × display)
- ถ้ามี element ที่โผล่บนมือถือผิด ให้แก้ด้วยวิธีที่ถูกต้อง เช่นให้ `tailwind.css` เป็นตัวควบคุม และลบ `.hidden !important` ที่เป็นต้นเหตุ หรือกำหนด utility แยกต่างหาก แล้วเพิ่ม regression test ใน `tests/test_browser_suite.py` ที่เช็ค computed display ของตัวอย่าง element เหล่านี้
- ตรวจ `.view.hidden` และ view อื่นว่าสลับหน้าแล้วไม่ซ้อน/ไม่ว่าง
- หลังแก้ CSS: rebuild Tailwind ถ้าจำเป็น และเพิ่มเลข `?v=` ใน `templates/index.html`

## 2. ช่องว่างของการตรวจรอบก่อน (พบบั๊กแค่ 5 ข้อ ซึ่งน้อยกว่าที่ผู้ใช้เจอจริง)

รอบนี้ให้ทดสอบแบบ **ผู้ใช้จริงทำ ไม่ใช่แค่ unit test** — เปิดแอปทดสอบ (พอร์ตแยก, DB ชั่วคราว) แล้วใช้ Playwright เดินตามสถานการณ์เหล่านี้ทีละข้อ บันทึกภาพหน้าจอเมื่อพบปัญหา

A. สถานการณ์ผู้ใช้ใหม่ตั้งแต่ศูนย์: สมัคร → สร้างองค์กร → เชิญสมาชิก → อัปโหลดเอกสาร 3 ไฟล์ (ใช้ไฟล์ใน `เอกสาร โปรจบ\เอกสารสินค้าตัวอย่างสำหรับอัปโหลด\`) → ถามแชท AI (mock โมเดล แต่ใช้ retrieval จริง) → ตรวจแหล่งอ้างอิงและคำตอบ "ไม่พบ"
B. สถานการณ์ผู้ใช้ 3 บทบาทใช้พร้อมกัน: admin อัปโหลด, member ถาม, owner เปลี่ยนสิทธิ์หมวดหมู่ ระหว่างนั้น ตรวจว่าสิทธิ์มีผลทันทีและไม่เห็นไฟล์ที่ไม่มีสิทธิ์
C. สถานการณ์บอท LINE (mock webhook + mock LINE API): ผู้ใช้ผูกแล้ว/ยังไม่ผูก/ถูกปิดใช้งาน × คำสั่งทุกชนิด (`/link`, ค้นหา, ค้นหา <ชื่อ>, ถามข้อมูลสินค้า, ถามนอกเรื่อง, ทักทาย, สติกเกอร์, รูปภาพ) ตรวจ payload ที่ส่งกลับทุกกรณี รวมความยาวและ URI
D. สถานการณ์ผิดพลาด: ผู้ให้บริการ AI ล่ม/timeout/429, Drive token หมดอายุ, LINE API ตอบ 400/429/500, อัปโหลดไฟล์เสีย — ต้องมีข้อความไทยที่เข้าใจได้ ไม่เงียบ ไม่ 500
E. สถานการณ์ restart: อัปโหลดค้างตอนปิดเซิร์ฟเวอร์ แล้วเปิดใหม่ — สถานะต้องไม่ค้าง INDEXING และ vector store กับ meta ต้องสอดคล้อง (ตรวจจำนวนท่อนเท่ากัน)
F. ข้อมูลภาษาไทยปนอักขระพิเศษในทุกช่องกรอก (ชื่อไฟล์, ชื่อองค์กร, ชื่อแผนก, หัวข้อกิจกรรม, ข้อความแชท) ตรวจการแสดงผลและการบันทึก

## 4. ความปลอดภัยเชิงลึก (ลงมือจริง ไม่ใช่แค่อ่านโค้ด)

- IDOR: ลองเรียกทุก endpoint ที่รับ id (ไฟล์, ผู้ใช้, แชท, กิจกรรม, ใบลา, drive log) ด้วยบัญชีองค์กรอื่นและบทบาท member — ทำเป็นตารางเทสต์อัตโนมัติ (endpoint × บทบาท × ผลที่ควรได้ 200/403/404)
- Path traversal / ชื่อไฟล์อันตรายในอัปโหลดและดาวน์โหลด, โทเค็นดาวน์โหลดหมดอายุ/ปลอม/ของไฟล์อื่น
- Rate limit: login, bind LINE, ใส่รหัสผูก, อัปโหลด, แชท AI — ตรวจว่าถูกจำกัดจริงและตอบ 429 พร้อมข้อความไทย
- IP ที่บันทึกใน audit: ตรวจว่าอ่านจาก header ของ Cloudflare Tunnel อย่างปลอดภัย (ไม่เชื่อ `X-Forwarded-For` จากผู้ใช้ตรงๆ ถ้าไม่ผ่าน tunnel) และไม่ใช่ 127.0.0.1 ทุกแถว
- ตรวจ log ว่าไม่มี secret/token/รหัสผ่านรั่ว (ค้นรูปแบบ `LINE_CHANNEL`, `Bearer`, `client_secret`, `password=` ในไฟล์ log ที่ทดสอบสร้าง)
