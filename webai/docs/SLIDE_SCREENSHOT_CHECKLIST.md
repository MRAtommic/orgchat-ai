## ภาพที่ขาด เรียงตามความสำคัญ (ต้องมี = ★)

### ★ 1. ล็อกอินด้วย LINE (ขอบเขตภาค 1 ระบุไว้ แต่ยังไม่มีภาพ)
- หน้าล็อกอินที่ **เห็นปุ่ม "เข้าสู่ระบบด้วย LINE"** ครบทุกวิธี
- หน้าขอสิทธิ์ของ LINE → เข้าระบบสำเร็จ (ครอบด้วยภาพ 2–3 เฟรม ต่อกันเป็นภาพเดียว)
- **ทำก่อนแคป:** ต้องแก้ค่า Channel secret ใน `.env` ให้ตรงก่อน (ตอนนี้ยังขึ้น `invalid client_secret`)

### ★ 2. การผูกบัญชี Google + LINE
- การ์ด "การเชื่อมต่อบัญชีผู้ใช้ (Connected Accounts & SSO)" แสดงว่า Google และ LINE ผูกแล้ว
- (ถ้าอธิบายเรื่องที่ผมแก้ไว้) หน้า "LINE นี้ผูกกับบัญชีอื่นอยู่ ต้องการย้ายไหม"

### ★ 3. ระบบสิทธิ์ผู้ใช้ (RBAC) และความปลอดภัยเซสชัน
- หน้าจัดการผู้ใช้/สมาชิกที่เห็นบทบาท Admin/Manager/Employee
- หน้า Security/นโยบายองค์กร (2FA, หมดเวลาเซสชัน) และหน้า Security Audit/audit logs
- ข้อความตอนใส่รหัสผ่านผิดหลายครั้ง (ล็อกบัญชีชั่วคราว)
- ตาราง/ภาพประกอบ: ตัวอย่างล็อกที่ระบบบันทึก IP เวลา กิจกรรม (ตรงกับ Test case 12 ในเล่ม)

### ★ 4. กระบวนการแปลงเอกสารเป็นเวกเตอร์ (ที่อาจารย์ถามให้โชว์)
- หน้าอัปโหลดไฟล์ → สถานะประมวลผล → READY (เห็นจำนวน chunks)
- เปิดดู chunks ของไฟล์ (ไอคอนรูปตา) ให้เห็นข้อความที่ตัดเป็นท่อน
- **ภาพหน้าจอเทอร์มินัลรัน `python tools/demo_embeddings.py`** ให้เห็นขั้น: ตัดท่อน → เวกเตอร์ 384 ตัว → เก็บ ChromaDB → ค้นหาตามความหมาย
- แผนภาพ Flow RAG (fig3_6 มีแล้ว ให้ใช้ประกอบ)

### ★ 5. การถามตอบ RAG ที่เห็นแหล่งที่มา และกรณีไม่มีข้อมูล
- ถามผ่านเว็บ/LINE แล้วคำตอบอ้างอิงเอกสาร (ชื่อไฟล์) ได้
- **ถามเรื่องที่ไม่มีในเอกสาร** แล้วบอตตอบปฏิเสธสุภาพ (Test case 9 ในเล่ม ยังไม่มีภาพ)
- คำตอบแบบ LINE Flex Message (การ์ด/ปุ่ม) (Test case 10 ยังไม่มีภาพ)

### ★ 6. Google Drive (บทที่ 4 มีหัวข้อนี้แต่ **ไม่มีภาพเลย**)
- หน้าเชื่อมต่อ Google Drive ในระบบ
- โฟลเดอร์ใน Google Drive ที่แยกตามปี/เดือน และไฟล์ที่ถูกอัปโหลดอยู่ข้างใน (ตรงกับ Test case 11)
- **ทำก่อนแคป:** เพื่อนคุณเพิ่งเจอ `internal_error` ตอนเชื่อม Drive ผมแก้ที่ต้นเหตุแล้ว ต้องรีสตาร์ตเซิร์ฟเวอร์ แล้วลองเชื่อมสำเร็จก่อน ผมยังไม่ได้ทดสอบกับ Google จริง

### ☆ 7. หลักฐานการทดสอบ
- เทอร์มินัลรัน pytest ผ่าน (ทีละไฟล์) แสดงจำนวนเทสต์ที่ผ่านจริง
- หน้า LINE rich menu (มีใน fig4_2 บางส่วนแล้ว)

## ข้อควรระวังก่อนแคปทุกภาพ
1. **ปิดบังข้อมูลลับ:** Channel secret, API key, token, `.env` ห้ามติดภาพ (Channel secret ของ LINE Login เคยหลุดในแชท ควรออกค่าใหม่)
2. **ข้อมูลส่วนบุคคล:** fig4_3 มีรหัสนักศึกษาและไฟล์เงินเดือน ควรแคปใหม่ด้วยข้อมูลตัวอย่าง หรือเบลอ
3. **ตั้งขนาดหน้าจอเดียวกัน** (เช่น 1440 กว้าง) ธีมเดียวกัน (ธีมมืดตามภาพเดิม) ภาพถึงจะดูกลมกลืน
4. ใส่คำบรรยายสั้นใต้ภาพ ว่ากำลังโชว์ฟีเจอร์ไหน ตรงกับ Test case ข้อไหน

## ⚠ ตัวเลขในสคริปต์สไลด์ที่ตรวจสอบไม่ได้และขัดกับเล่ม (สำคัญ)
สคริปต์ `AUCC2027_Presentation_Script.md` ระบุ: ตอบภายใน **1.84 วินาที**, **15 Test Cases** ผ่าน 100%, OCR แม่นยำ **96.4%** (50 สลิป 5 ธนาคาร), RAG ถูกต้อง **94.8%** (50 คำถาม), ความพึงพอใจ **N=20, Mean 4.65, S.D. 0.48**
แต่บทที่ 4 ของเล่มเขียนว่าภาค 1 มี **12 Test Cases**, และระบุว่า OCR, ลางาน, แดชบอร์ด, การทดสอบกับผู้ใช้จริง **ยังไม่ดำเนินการ** (เป็นงานภาค 2)
- ถ้าตัวเลขเหล่านี้ **ไม่ได้มาจากการวัดจริง** ห้ามใส่ในสไลด์ในฐานะผลการทดลอง ให้ลบ หรือระบุเป็น "เป้าหมาย" เท่านั้น กรรมการมักถามข้อมูลดิบ
- ถ้าวัดจริงแล้ว ให้เตรียมตารางข้อมูลดิบ (ชุดคำถาม คำตอบที่ได้ ผลถูก/ผิด) ไว้แสดง
- ให้จำนวน Test Cases ในสไลด์กับเล่มตรงกัน
- ผมตรวจไม่ได้ว่าตัวเลขพวกนี้มาจากไหน จึงเตือนไว้เฉยๆ
