# แผนตรวจสอบบั๊กทั้งระบบ (Full QA Audit) — สำหรับ anti

เป้าหมาย: ผู้ใช้ใช้งานจริงแล้วเจอบั๊กหลายจุด ให้ anti **ไล่ทดสอบทุกฟังก์ชัน ทุกรูปแบบการใช้งาน** แล้วรายงานและแก้ โดยทำเป็นรอบ ไม่ข้ามหัวข้อ
โปรเจกต์: `webai/` (Flask + Flask-SocketIO, SQLite, LINE OA, RAG, Google Drive/Sheets)

---

## 0. กฎเหล็ก (ห้ามฝ่าฝืน)

1. **ห้ามอ่าน แก้ หรือ commit `webai/.env`** (มี secret จริง) และห้ามใส่ secret/API key/อีเมลจริงในรายงานหรือภาพ
2. **ห้ามทดสอบกับ `chat_history.db` จริงหรือ KB จริง** ใช้ฐานข้อมูลและโฟลเดอร์ข้อมูลชั่วคราวเสมอ (temp `DB_PATH`/`DATA_DIR`), ตั้ง `VECTOR_BACKEND=python`
3. แอปโหลด `.env` อัตโนมัติ → ตอนรันเซิร์ฟเวอร์ทดสอบ **ต้องเคลียร์ค่า external ให้ว่าง** (`LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET`, `LINE_LOGIN_*`, `GOOGLE_*`, `GROQ_API_KEY`, `GEMINI_API_KEY`) ไม่เช่นนั้นอาจยิง LINE/Google จริง ให้ mock ฝั่ง requests แทน
4. **ห้าม push git** และห้ามเรียก endpoint ที่ทำลายข้อมูลกับระบบจริง
5. รันพอร์ตทดสอบแยกจากพอร์ตจริง (จริงใช้ 5005) ทดสอบเสร็จ **ปิดเซิร์ฟเวอร์ทดสอบทุกตัว**
6. pytest รัน **ทีละไฟล์เท่านั้น** (รันทั้งชุดพร้อมกันเกิดปัญหา OpenBLAS memory) เช่น `python -m pytest tests/test_auth.py -q`
7. เขียนสคริปต์ด้วยไฟล์ ไม่ใช่ heredoc ยาวใน shell (เครื่องมือบางตัวทำ backslash/quote เพี้ยน)
8. **ก่อนแก้ไฟล์ใด ให้ตรวจว่าไม่มี agent อื่นแก้ไฟล์เดียวกันอยู่** และหลังแก้ให้ตรวจว่าการแก้ไขยังอยู่ (เคยมีการเขียนทับกัน 2 ครั้ง)
9. ทุกบั๊กที่แก้ **ต้องมีเทสต์กันถอยหลัง** (regression test) และเทสต์ต้องล้มเมื่อโค้ดเดิม ถ้าไม่ล้ม แปลว่าเทสต์ไม่ได้ทดสอบบั๊กนั้นจริง
10. พฤติกรรมเปลี่ยน Python → ผู้ใช้ต้อง restart เซิร์ฟเวอร์จริง / static+templates โหลดสดด้วย Ctrl+F5 (แจ้งในรายงาน)

## 1. วิธีทำงาน

- **รอบที่ 1 สำรวจ:** ทดสอบทุกหัวข้อด้านล่างโดยไม่แก้โค้ด สร้างรายงาน `docs/QA_AUDIT_REPORT.md` (ตารางบั๊ก: ID, หัวข้อ, ขั้นตอนทำซ้ำ, ผลที่เกิด, ผลที่ควรเป็น, ความรุนแรง P0–P3, ไฟล์/บรรทัดที่สงสัย)
- **รอบที่ 2 แก้:** เรียงตามความรุนแรง P0 → P3 แก้ทีละบั๊ก + เทสต์ + รันเทสต์ไฟล์ที่เกี่ยว
- **รอบที่ 3 ยืนยัน:** รันเทสต์ทุกไฟล์ทีละไฟล์ซ้ำ (รายการในหัวข้อ 12) และไล่ทดสอบหน้าเว็บในเบราว์เซอร์จริง (Playwright `channel="chrome"`) ตามรายการเดิมอีกรอบ
- **ความรุนแรง:** P0 ข้อมูลรั่ว/สิทธิ์ผิด/เข้าสู่ระบบไม่ได้/ข้อมูลหาย · P1 ฟีเจอร์หลักใช้ไม่ได้ · P2 ใช้ได้แต่ผิดพลาด/สับสน · P3 หน้าตา/ข้อความ
- รายงานเป็นภาษาไทย แยกบั๊กที่ "ยืนยันซ้ำได้" ออกจาก "สงสัยแต่ยังซ้ำไม่ได้"

## 2. ระบบสมาชิกและการยืนยันตัวตน (`routes/auth.py`, `db/`, `static/js/auth*`)

ทดสอบทุกข้อทั้งทาง UI และเรียก API ตรง:

- สมัครสมาชิก: ข้อมูลครบ/ขาด, username ซ้ำ (ตัวพิมพ์เล็กใหญ่), อีเมลซ้ำ, รหัสผ่านสั้น/ง่าย, อักขระพิเศษ/ภาษาไทย/emoji, ช่องว่างหัวท้าย, SQL/HTML/script ในทุกช่อง, สร้างองค์กรพร้อมสมัคร
- เข้าสู่ระบบ: ถูก/ผิด, ผิด 5 ครั้งแล้วล็อก 15 นาที (ล็อกหมดเวลาถูกต้องไหม, รีเซ็ตตัวนับหลังสำเร็จไหม, ล็อกแยกตามผู้ใช้หรือ IP, ข้อความแจ้ง), Flask-Limiter ต่อนาที, ผู้ใช้ไม่มีอยู่ (ข้อความต้องไม่บอกว่า user ไม่มี), ผู้ใช้ถูกปิดใช้งาน
- เซสชัน: คุกกี้ (Secure/HttpOnly/SameSite), idle timeout, session_version (เปลี่ยนรหัสผ่านแล้วเครื่องอื่นต้องหลุด), UA fingerprint (**ตรวจว่าอัปเดตเบราว์เซอร์/เปลี่ยน UA เล็กน้อยแล้วไม่ถูกเตะออกโดยไม่จำเป็น**), logout แล้ว back ในเบราว์เซอร์ต้องเข้าไม่ได้, เปิดหลายแท็บ/หลายเครื่อง
- CSRF: ทุก POST/PUT/DELETE ที่เปลี่ยนข้อมูลต้องตรวจ `X-CSRF-Token`, ลองไม่ส่ง/ส่งผิด/โทเค็นหมดอายุ, ตรวจว่าไม่มี endpoint ที่หลุด
- ลืมรหัสผ่าน/เปลี่ยนรหัสผ่าน/รีเซ็ต: โทเค็นใช้ซ้ำได้ไหม, หมดอายุไหม, ทำให้เซสชันอื่นหลุดไหม
- 2FA: เปิด/ปิด/ยืนยันโค้ดผิด/ถูก/หมดอายุ, นโยบายบังคับ 2FA ระดับองค์กร, สำรองโค้ด (ถ้ามี)
- QR Code login (ให้มือถือสแกน): สร้าง/หมดอายุ/ใช้ซ้ำ/สแกนด้วยบัญชีอื่น/polling
- Audit log: ทุกเหตุการณ์ข้างบนต้องมีบันทึก (ผู้ใช้ เวลา กิจกรรม สถานะ IP) และหน้า Audit/Security Audit ต้องแสดงครบ ไม่ error เมื่อ field ว่าง

## 3. LINE Login และการผูกบัญชี LINE (`routes/auth.py`, `routes/line_*.py`, `db/settings.py`)

ข้อเท็จจริงของระบบ: LINE Login กับ Messaging bot ใช้ user ID **คนละค่า** (`line_login_id` กับ `line_user_id`) ต้องไม่สับสน

- ปุ่ม "ลงชื่อเข้าใช้ด้วย LINE": state ผิด/หายกลางทาง/callback ซ้ำ/ผู้ใช้กดปฏิเสธที่ LINE/network error ต้องแสดงข้อความถูกต้อง ไม่ 500
- ผู้ใช้ใหม่ vs ผู้ใช้ที่ผูกแล้ว: ต้องเข้าบัญชีเดิม, ต้อง **ไม่ผูกอัตโนมัติด้วยอีเมล**, ไม่ตกไปเป็น "Admin/few" โดยไม่ตั้งใจ
- ผูกด้วยรหัส (`/link` ในบอท): รหัส 8 ตัว อายุ 10 นาที ใช้ครั้งเดียว — ทดสอบหมดอายุ, ใช้ซ้ำ, พิมพ์ตัวเล็ก/ขีด/ช่องว่าง (`normalize_link_code`), ผิดหลายครั้ง (rate limit), รหัสของคนอื่น
- `/api/user/bind-line-direct` ต้องรับเฉพาะรหัส/โทเค็นจากบอท ส่ง `line_user_id` ดิบต้อง 400
- LINE ที่ผูกกับบัญชีอื่นอยู่: ต้องมีหน้ายืนยันย้าย (`confirm-move`), ทดสอบยืนยัน/ยกเลิก, ผู้ใช้เดิมต้องถูกถอดผูกจริง
- ลิงก์วิเศษ `/line/link_magic` (+ ปุ่ม Google ในหน้านั้น): โทเค็นหมดอายุ/ใช้ซ้ำ/ผู้ใช้ไม่ได้ล็อกอิน/ล็อกอินคนละบัญชี
- ยกเลิกการผูก LINE: หลังยกเลิกบอทต้องไม่ตอบข้อมูลองค์กรให้ LINE นั้น
- Flex card ในบอท (ผูกบัญชี/ลิงก์): URI ต้องผ่าน LINE API (เคยพังเพราะชื่อไฟล์ภาษาไทยไม่ encode → "Invalid action URI"), ตรวจ fallback เป็นข้อความธรรมดา
- ตรวจว่าสถานะ "ผูกแล้ว" ในหน้าเว็บ (ตั้งค่า > บัญชีที่เชื่อมต่อ) ตรงกับฐานข้อมูลเสมอ

## 4. Google OAuth / Sign-in / Drive / Sheets (`routes/auth.py`, `google_*`, Drive routes)

- ลงชื่อเข้าใช้ด้วย Google (GIS ID token): token ผิด/หมดอายุ/audience ผิด, ผู้ใช้ใหม่/เก่า, อีเมลซ้ำกับบัญชีรหัสผ่าน (ต้องไม่รวมบัญชีเงียบๆ), `/api/user/bind-google`
- เชื่อม Google Drive/Sheets ระดับองค์กร: callback สำเร็จ/ปฏิเสธ/scope ไม่ครบ/ซ้ำ, ใครกดได้ (superadmin/admin/org-admin เท่านั้น), **ยกเลิกการเชื่อมต่อ** ต้องทำงานทุกบทบาทที่มีสิทธิ์ (เคยกดไม่ได้)
- หน้า "เชื่อมต่อแล้ว" ต้องไม่แสดง toast error สีแดงค้าง (เคยเห็นในหน้า org Drive)
- อัปโหลดไฟล์ขึ้น Drive: โฟลเดอร์ ปี/เดือน สร้างอัตโนมัติ, ชื่อไฟล์ภาษาไทย/อักขระพิเศษ/ชื่อซ้ำ, ไฟล์ใหญ่, token หมดอายุ→refresh, Drive เต็ม/ถูกลบโฟลเดอร์, `drive_logs` บันทึกครบ
- แอปเป็นสถานะ unverified (จำกัดผู้ใช้ทดสอบ) → ตรวจว่าข้อความ error เมื่อ user ถูกจำกัดสื่อความชัด

## 5. คลังความรู้ RAG (`rag_engine.py`, `routes/kb*`, `citation_filter.py`)

- อัปโหลด: PDF/TXT/CSV/DOCX/XLSX/รูป, ไฟล์ว่าง, ไฟล์เสีย, ไฟล์ใหญ่มาก, ชื่อภาษาไทย/ยาว/มีอักขระพิเศษ, ไฟล์ซ้ำ (แฮช SHA-256 ต้องแจ้งเตือนและไม่ซ้ำ), **อัปโหลดหลายไฟล์พร้อมกัน** (เคยค้างสถานะ INDEXING เพราะ race; ตรวจ `_META_LOCK` ยังทำงาน, ทดสอบ 10–20 ไฟล์พร้อมกัน), อัปโหลดแล้วปิดแท็บกลางทาง
- สถานะไฟล์: INDEXING→READY/FAILED ถูกต้อง, FAILED ต้องมีข้อความสาเหตุ, ปุ่มลองใหม่, ลบไฟล์แล้วเวกเตอร์ถูกลบจริง (ค้นหาแล้วไม่เจออีก), เปลี่ยนหมวดหมู่/สิทธิ์แล้วมีผลทันที
- การสร้างเวกเตอร์: FastEmbed local 384 มิติ, ตัดท่อน 800/overlap, ข้อความไทยล้วน/อังกฤษล้วน/ผสม/ตาราง, `PurePythonVectorStore` (JSON `chroma_db_fallback.json`) vs `ChromaStore` (`VECTOR_BACKEND=chroma`) ผลต้องสอดคล้อง และมี metadata ตรงกับไฟล์ (เคย JSON 109 ท่อน vs meta 315) — ตรวจความสอดคล้องระหว่าง meta กับ vector store, สตาร์ตแอปแล้วข้อมูลไม่ถูกล้างผิดพลาด (มีขั้นตอน cleanup ตอนสตาร์ต ต้องไม่ลบไฟล์ที่ยังใช้อยู่)
- การค้นคืน `retrieve_context`: คำถามพิมพ์ผิด (เช่น "แบนด์", "thum toe"), คำพ้อง, ถามตามบริบทหลายรอบ (follow-up, `tests/test_rag_followup.py` มี 1 เคสที่ล้ม: greeting ไม่ถูกตัด — ให้ตรวจว่าใช่บั๊กจริงและแก้), ถามเรื่องที่ไม่มีในเอกสาร (ต้องตอบสั้น "ยังไม่พบ" ไม่แต่ง), ถามเรื่องที่มีในไฟล์ที่ผู้ใช้ **ไม่มีสิทธิ์หมวดหมู่นั้น** (ต้องไม่รั่ว)
- แหล่งอ้างอิง: ต้องแสดงเฉพาะไฟล์ที่ใช้ตอบจริง (`select_cited_sources`), คำตอบ "ไม่พบ" ไม่แนบแหล่ง, ทดสอบเพิ่มด้วยคำถามหลากหลาย 30+ ข้อ ตรวจว่าไม่ตัดแหล่งที่ใช้จริงทิ้ง และไม่แนบไฟล์ไม่เกี่ยว
- ไฟล์ตัวอย่างในโฟลเดอร์ `เอกสาร โปรจบ\เอกสารสินค้าตัวอย่างสำหรับอัปโหลด\` (duit, thumb toe, ภาพรวมแบรนด์) ใช้ทดสอบถามตอบ

## 6. แชทบอท LINE OA (`routes/line_webhook.py`, `routes/line_flex.py`)

(ให้ mock LINE API; ตรวจ payload ที่จะส่ง)

- Webhook: signature ถูก/ผิด/ไม่มี, event ซ้ำ (redelivery), หลาย event ใน request เดียว, event ชนิดอื่น (follow, unfollow, join, postback, image, sticker, location), ข้อความยาวมาก, emoji, ข้อความว่าง
- ถามตอบ RAG: ตอบสั้น ตรงประเด็น, ไม่มี `**`/markdown ดิบ (`line_plain_text`), ท้ายคำตอบมีแหล่งอ้างอิง+ลิงก์เฉพาะไฟล์ที่ใช้, ความยาวไม่เกินข้อจำกัด LINE (5000 ตัวอักษร/5 ข้อความ), ผู้ใช้ที่ยังไม่ผูกบัญชีต้องไม่ได้ข้อมูลองค์กร
- ค้นหาไฟล์: `ค้นหา <ชื่อ>`, `ค้นหา` เฉยๆ (ต้องแสดงรายการไฟล์), คำที่กำกวม (ต้องไม่ตกไปเป็นค้นไฟล์ผิด และไม่ตกไปเป็นถาม AI ผิด), ผลค้นหา 0/1/หลายไฟล์, การ์ด Flex + fallback ข้อความธรรมดา, ลิงก์ดาวน์โหลด (URL encode ชื่อภาษาไทย, โทเค็นอายุ 7 วัน, หมดอายุแล้วต้องขึ้นข้อความชัด), **กรองสิทธิ์ตามหมวดหมู่** (`_kb_file_visible`)
- คำสั่งอื่นในบอท: `/link`, เมนู rich menu, ปฏิทิน/กิจกรรม, ลางาน/อนุมัติ (Flex), สรุปรายงาน ฯลฯ ทุกคำสั่งต้องมีทางตอบกลับเมื่อผิดพลาด ไม่เงียบ
- ผู้ใช้ที่ไม่มีสิทธิ์/ถูกปิดใช้งาน/หมดโควตา AI: ข้อความต้องเป็นมิตรและไม่เปิดเผยข้อมูลภายใน
- ตรวจ `reply_to_line` เมื่อ LINE ตอบ 400/429/500 ว่า fallback ทำงานและไม่วนซ้ำ, replyToken ใช้ซ้ำ/หมดอายุ
- Prompt ของโมเดล: กฎ "ไม่พบข้อมูลให้ตอบสั้น ≤2 ประโยค ห้ามเดา ห้ามเสนอหลายทาง" ยังทำงานจริงกับโมเดล (ถ้าไม่มี API key ให้ตรวจ prompt สร้างถูก)

- แหล่งอ้างอิงใต้คำตอบ (`sources_final`): ชิปไฟล์แสดงเฉพาะที่ใช้ตอบ, คลิกเปิดไฟล์ได้, **บนมือถือ** (ตรวจ hover/toggle), ประวัติแชทเก่าโหลดแล้วยังเห็นแหล่ง
- ประวัติการสนทนา: สร้าง/ลบ/เปลี่ยนชื่อ/ค้นหา, ข้ามอุปกรณ์, ผู้ใช้คนละคนต้องไม่เห็นกัน
- แนบไฟล์ในแชท (โหมดแนบไฟล์โดยตรง), เลือกโมเดล/โฟลเดอร์บริบท
- XSS: markdown/HTML ในข้อความผู้ใช้และคำตอบ AI ต้อง sanitize (เคยอุดช่องหนึ่งแล้ว ตรวจให้ทั่วทุกจุดที่ใช้ innerHTML)

## 8. หน้าเว็บ, UI และ UX (`templates/`, `static/js`, `static/css`)

ทดสอบด้วยเบราว์เซอร์จริงทุกหน้า ทั้ง **เดสก์ท็อป 1920/1440/1280, แท็บเล็ต 768, มือถือ 375/390** และโหมดสว่าง/มืด:

- ทุกเมนูซ้ายและทุกหน้า: โหลดได้ ไม่มี error ใน console, ไม่มี network 4xx/5xx ที่ไม่ควรมี, ไม่มี element ซ้อน/ล้น/ถูกตัด
- **ปัญหาที่ทราบ:** `.hidden{display:none!important}` ใน `components.css`/`style.css` ทำให้ element ที่ใช้ `hidden md:*`/`sm:flex` ราว 22 จุดในหน้า home ไม่แสดงบนจอใหญ่ → ไล่ตรวจทุกจุดว่าควรแสดงหรือไม่ แล้วแก้ที่ต้นเหตุอย่างปลอดภัย
- Tailwind เป็นไฟล์คอมไพล์ล่วงหน้า (`static/css/tailwind.css`): คลาสใหม่ที่เพิ่งใช้อาจไม่มีในไฟล์ → ตรวจว่ามีคลาสที่ใช้แต่ไม่ถูกคอมไพล์ไหม ถ้าเพิ่มต้อง rebuild: ในโฟลเดอร์ `tools/tailwind` รัน `npx tailwindcss@3.4.16 -c tailwind.config.js -i input.css -o ../../static/css/tailwind.css --minify` แล้วเพิ่มเลข `?v=` ใน `templates/index.html`
- ปฏิทิน/กิจกรรม: การ์ดซ้าย/ขวา, ปฏิทินเต็มเดือนไม่ย่อ, คลิกวันดูรายละเอียดเต็ม, สร้าง/แก้/ลบกิจกรรม, วันที่ข้ามเดือน/ปี, เขตเวลา, กิจกรรมซ้อนกัน (ดู `docs/PLAN_CALENDAR_REDESIGN.md`)
- ฟอนต์ที่ผู้ใช้เลือก (ดู `docs/PLAN_FONT_PREFS.md`): บันทึกต่อผู้ใช้, โหลดใหม่แล้วคงอยู่, ไม่กระทบคนอื่น
- ฟอร์มทุกหน้า: validation, ข้อความ error ภาษาไทยถูกต้อง, ปุ่มกดซ้ำ, loading state, toast ไม่ค้าง
- การเข้าถึง: โฟกัสด้วยคีย์บอร์ด, ปุ่มมี label, คอนทราสต์

## 9. ผู้ดูแล, บทบาทและสิทธิ์ (RBAC), ความปลอดภัย

- บทบาท: owner/superadmin/admin/member และสิทธิ์รายฟีเจอร์ ทดสอบ **ทุกคู่ (บทบาท × endpoint)** ว่ากันสิทธิ์ถูก ทั้ง UI ซ่อนและ **API ตรวจฝั่งเซิร์ฟเวอร์** (ลองเรียก API ตรงด้วยบัญชี member)
- Multi-tenant: ผู้ใช้องค์กร A ต้องเข้า/เห็น/แก้ข้อมูลองค์กร B ไม่ได้ ทุก endpoint (IDOR: ลองเปลี่ยน id ใน URL/body ของไฟล์, ผู้ใช้, แชท, กิจกรรม, Drive, audit)
- หน้าสมาชิกและบทบาท: เชิญ/เปลี่ยนบทบาท/ลบ/ปิดใช้งาน, ลบเจ้าขององค์กร (ต้องป้องกัน), ลดบทบาทตัวเอง
- Super Admin & Audit Trail & Security Audit (หน้านี้ต้องกดปุ่มเข้า `showView('security-audit'); loadSecurityAuditDashboard()`): ตัวกรอง, การแบ่งหน้า, ข้อมูลว่าง, IP ถูกต้อง (ผ่าน Cloudflare Tunnel ต้องอ่าน IP จริงจาก header ที่เชื่อถือได้ ไม่ใช่ IP ของ tunnel)
- Header/นโยบาย: CSP (ปัจจุบันยังมี `unsafe-inline` — บันทึกเป็นข้อเสนอแนะ ไม่ต้องแก้ถ้าเสี่ยงทำหน้าแตก), CORS, cookie flags, rate limit ทุก endpoint ที่เสี่ยง (login, bind, upload, AI chat)
- Injection: SQL injection ในทุกพารามิเตอร์ (ควรเป็น parameterized query ทั้งหมด), path traversal ในดาวน์โหลด/อัปโหลดไฟล์, SSRF ถ้ามีการดึง URL, upload ไฟล์อันตราย (ชื่อ `../`, นามสกุลปลอม)
- Secret: ตรวจว่าไม่มี secret ถูกพิมพ์ลง log/response/หน้าเว็บ (มี LINE Login Channel secret เคยรั่วในแชท ผู้ใช้ต้อง Issue ใหม่เองและอัปเดต `.env`)

## 10. ความทนทานและประสิทธิภาพ

- การใช้งานพร้อมกัน: 20–50 ผู้ใช้ยิง API/แชท/อัปโหลดพร้อมกัน (SQLite WAL, `database is locked`), Socket.IO หลายแท็บ/หลายเครื่อง/reconnect
- Restart กลางงาน: อัปโหลดค้างตอนเซิร์ฟเวอร์ restart → สถานะไม่ค้าง INDEXING ถาวร
- ไฟล์ข้อมูลเสีย/ว่าง (`file_meta.json`, `chroma_db_fallback.json`, DB) → แอปต้องไม่พังตั้งแต่สตาร์ต
- ค่า config ขาด/ผิด (ไม่มี API key, ไม่มี Google client) → ฟีเจอร์นั้นแจ้งชัด ฟีเจอร์อื่นยังใช้ได้
- ช่วงเวลา/เขตเวลา: เวลาที่เก็บ/แสดง (UTC vs เวลาไทย) สอดคล้องทั้ง audit log, ปฏิทิน, ใบลา, ลิงก์หมดอายุ
- หน่วยความจำ/เวลาตอบ: ถามตอบด้วย KB ใหญ่ (หลายพันท่อน), ค้นหาช้าไหม
